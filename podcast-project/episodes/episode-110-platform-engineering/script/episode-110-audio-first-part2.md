- **Passives (7-8 rating)**: "Society okay hai, but improvement ki scope hai"  
- **Detractors (1-6 rating)**: "Society mein bohot problems hain, shifting soch raha hun"

**Society NPS Score = ((Promoters - Detractors) / Total Responses) × 100**

Example: 100 residents survey mein
- Promoters: 60 residents (society recommend karenge)
- Detractors: 15 residents (society se disappointed)
- Society NPS = ((60-15)/100) × 100 = 45% (Good score)

### Pipeline Optimization Patterns - Mumbai Dabba Delivery System

Mumbai dabba delivery system perfect example hai optimized pipeline ka. Har step perfectly coordinated hai - ghar se pickup, train journey, office delivery. Same principle platform engineering mein CI/CD pipeline mein apply hoti hai.

**Mumbai Dabba System = CI/CD Pipeline Analogy:**

**Traditional Dabba Delivery (Old Style):**
- Each dabba individually handled
- No coordination between pickup and delivery  
- Delays accumulate at each step
- Quality check only at end customer

**Optimized Dabba System (Modern CI/CD Style):**
- Batch processing at each station
- Parallel route optimization
- Quality checks at multiple points
- Real-time tracking and feedback

**CI/CD Pipeline Optimization - Mumbai Dabba Style:**

**Morning Dabba Collection Phase (Build Stage):**
```
Parallel Collection Routes (Parallel Build Jobs):
Route 1: Andheri pickup points (Unit tests)
Route 2: Bandra pickup points (Code quality checks)  
Route 3: Santacruz pickup points (Security scanning)
Route 4: Khar pickup points (Dependency checks)

All routes converge at Andheri station by 11 AM
Maximum parallel workers: 4 collection teams
Timeout: Each route must complete in 45 minutes
```

**Train Journey Phase (Integration Stage):**
```
Quality Control During Transit:
Check 1: Dabba sealing and labeling (Integration tests)
Check 2: Temperature maintenance (Contract tests)
Check 3: Delivery address verification (Performance tests)

All checks happen simultaneously during train journey
Depends on successful morning collection
Quality failures = automatic route back to source
```

**Office Delivery Phase (Deployment Stage):**
```
Delivery Strategy Options:
Blue-Green Delivery: Deliver to alternate office floors first, if successful then normal floors
Canary Delivery: Deliver to 10% customers first, monitor feedback
Rolling Delivery: Floor by floor delivery with feedback at each floor

Rollback Triggers:
- Customer complaints > 2 per delivery batch
- Dabba temperature not maintained
- Wrong delivery address errors > 5%
```

**Smart Caching in Dabba System - Build Optimization:**

**Dabba Preparation Optimization:**
```
Base Ingredients Caching (Docker Layer Caching):
- Rice, dal, vegetables pre-cooked in bulk (Base images pre-built)
- Common masalas pre-ground and stored (Dependency layers cached)
- Reusable containers cleaned and ready (Multi-stage optimization)

Kitchen Workflow Caching:
- Recipes standardized and documented (Build script caching)
- Cooking equipment pre-setup (Development environment cached)
- Quality check checklists ready (Test automation cached)
```

**Result**: Dabba preparation time 3 hours se 45 minutes (75% time saving)
